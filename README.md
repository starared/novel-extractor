# 书境：整本 TXT 小说提取器

一个本地运行的中文网页。创作者**直接上传 `.txt`**，可选填卡名、扮演视角、起始场景等开场白要求，不需要切章或预先标注。产物为内嵌世界书的 Character Card V2 PNG 和可单独导入的 SillyTavern 世界书 JSON。Python 标准库实现，无前端构建步骤。

## Docker 启动与网页配置

仓库中的 `compose.override.yaml` 是维护者服务器专用配置。通用安装请使用下文的 `-f compose.yaml`，避免加载本机网络、数据目录和版本镜像设置。本机运维见 [DEPLOYMENT.md](DEPLOYMENT.md)。

在安装了 Docker Engine 和 Compose v2 的服务器或 Docker Desktop 上，克隆本仓库（或从 Releases 下载并解压对应架构的源码包），进入含 `Dockerfile` 的目录，运行：

```powershell
docker compose -f compose.yaml up --build -d
```

**选择端口：** 不配置时，访问 <http://localhost:49152>。如需更改，在 `compose.yaml` 同目录新建或编辑 `.env`（保留已有设置）：

```dotenv
PORT=53001
# 可选：宿主机端口与容器不同时，取消下一行注释
# HOST_PORT=53002
```

只设 `PORT=53001` 时，浏览器和容器都使用 `53001`；额外设置 `HOST_PORT=53002` 时，浏览器访问 `http://localhost:53002`，容器仍监听 `53001`。也可以只设 `HOST_PORT`，只改服务器端口。请选择未被占用的高位端口。用 `docker compose -f compose.yaml up -d` 应用端口变更，不用重建镜像；`docker compose -f compose.yaml ps` 可查看实际映射。

网页中打开 **模型设置**，填写 API 根地址和可选 API Key，点击 **拉取可用模型**，从列表选择后保存。拉取通过后端请求该地址的 `GET /models`，不下载模型权重，不改动已保存设置。服务不支持此接口时可手填模型 ID。在模型设置中勾选「流式生成」并保存，可以在提取和生成开场白时预览最近的模型输出。默认关闭。保存只检查格式；新模型节点使用新设置，正在运行的节点不会切换模型。

远程服务器默认不向公网暴露端口。例如服务器端口选了 `53002`，在**自己的电脑**执行 `ssh -N -L 53003:127.0.0.1:53002 用户名@服务器地址`，保持连接后访问 `http://localhost:53003`。将 `53003` 换成本机空闲端口，将 `53002` 换成实际的服务器端口。本服务无登录功能；多人使用前请自行设置带身份认证的 HTTPS 反向代理。

地址必须是 OpenAI 兼容 API 的根地址（如 `https://api.openai.com/v1`，不带 `/chat/completions`）。Docker 访问宿主机 Ollama 可用 `http://host.docker.internal:11434/v1`，模型名填该服务已安装的名称，无鉴权可留空。远程服务请使用 HTTPS。建议上下文至少 32k tokens 并支持中文 JSON 输出。镜像不自带模型。

配置保存在服务端 Docker 命名卷 `model-settings` 中：刷新页面、重启、在同一 Compose 项目下重建容器都会保留；`docker compose -f compose.yaml down -v` **会删除配置**。首次保存前沿用原有 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY` 环境变量，之后网页配置优先。密钥不回显，不写入浏览器存储；相同地址留空保留旧密钥，勾选可清除，更换地址需重新填密钥。密钥文件不加密，请保护数据卷及其备份。设置对整个实例生效，没有账户隔离；默认仅本机访问，不要公开部署。

## GitHub 发布和免构建部署

维护者：将**整个项目根目录**推送到自己的 GitHub 仓库（包括 `.github/workflows/publish.yml`，不要上传 `.env` 或 `data/`）。启用 GitHub Actions 并允许工作流发布 Packages 和 Releases。推送版本标签（例如首次发布时执行 `git tag v1.0.0` 和 `git push origin v1.0.0`）后，工作流运行测试，构建 `linux/amd64`、`linux/arm64`，将同一多架构镜像以版本标签和 `latest` 推送到 GHCR，并把两个独立源码 ZIP 附在 Release 中。要允许匿名拉取，请将 GHCR 包的可见性设为 Public。只推送代码不打标签也可用源码部署，但不会触发镜像发布。

用户：`uname -m` 显示 `x86_64` 选 AMD64，`aarch64` 选 ARM64。这两个版本的 Python 代码一致，源码包的 Compose 文件锁定不同目标平台。仓库根目录的 Compose 则默认使用服务器原生平台。在完整仓库运行 `python scripts/package_sources.py` 可重新生成 `dist/` 下的两个包。

镜像发布后，在 Linux 服务器直接运行下面的命令（将 `owner/repo` 和 `v1.0.0` 换成实际的小写仓库路径和版本，无需克隆源码）：

```sh
PORT=53001                      # 容器监听端口，自选
HOST_PORT=53002                 # 服务器端口，自选，也可以与 PORT 相同
docker run -d --name novel-extractor --restart unless-stopped --read-only \
  -e PORT="$PORT" -p "127.0.0.1:${HOST_PORT}:${PORT}" \
  -v novel-extractor_model-settings:/app/data \
  --add-host host.docker.internal:host-gateway \
  ghcr.io/owner/repo:v1.0.0
```

Docker 会自动选择服务器的 CPU 架构。以上两种部署方式任选一种，不要同时占用同一端口。在执行上述命令的终端用 `curl -fsS "http://127.0.0.1:${HOST_PORT}/health"` 验证服务，再通过 SSH 隧道使用网页。

## 从小说到角色卡

打开页面即可选择 TXT 或粘贴正文。素材、提取、世界书和开场白四步同时显示，可单独折叠。首次上传或跳过素材时才开始记录进度，进度仅供当前页面使用，请在刷新或关闭前下载需要的结果。

1. **素材**：选择整本 TXT 并上传，或跳过。没有应用级小说大小上限。服务分块写入数据卷中的临时文件，流式验证 UTF-8、带 BOM 的 UTF-16、GB18030/GBK，不要求整本装入内存。实际仍受磁盘、网络和反向代理的请求大小/超时配置限制。上传本身不使用模型。
2. **提取**：选类别、每段长度、提取重点后才逐段调用模型。长篇可能产生大量调用；一次确认覆盖此次提取的全部分段。一个实例同时运行一个模型节点。失败后可调整参数重试或跳过；跳过素材时也应跳过提取。
3. **世界书**：审阅候选设定、原文引证、蓝绿灯和插入方式，可从零添加条目，确认后进入下一节点。跳过此节点不保留世界书。匹配引文不代表推论正确。
4. 模型判断全局性，程序只让全局文风、叙事原则、世界规则常驻（最多四条蓝灯）；其余绿灯使用设定名、人物名、别称等关键词。插入位置按类型推荐：文风和规则在角色定义前，事件在聊天深度 4，其他在角色定义后。编辑器支持关闭、切换灯色、关键词、位置、顺序、深度、消息身份。绿灯是“命中任一主关键词”，未使用向量触发。实际注入还受 ST 扫描范围、预算和聊天设置影响。
5. **开场白**：分别填写首条消息的场景要求与角色扮演要求，生成 first_mes 和 description，也可手写，或输入要求让模型生成草稿。生成后停留在本节点，可修改、重新生成或跳过。**导出**：按需下载内嵌世界书的 PNG 角色卡、独立世界书 JSON，或直接结束。PNG 可在 SillyTavern 角色管理中导入，世界书 JSON 则从 World Info 面板导入；不要重复启用同一份设定。

## 数据与限制

模型节点才会发送素材给模型服务。跳过模型节点可以完全手工制作。审阅世界书时可以调整类别并重新提取。若一段只提取出文风、叙事逻辑或没有有效条目，且已选实体或事件等类别，程序会针对这些类别补提一次。上传原文在确认或跳过世界书、跳过提取或换一本小说时释放。制作进度、开篇短摘和结果保存在进程内存中；浏览器不再持久保存审阅草稿。重启会清空制作进度。开始处理新素材时，会清理超过一天未活动的空闲记录。成功段的候选与引文另存到数据卷 SQLite，同一文件、标题、模型和提取参数可复用，超过七天的记录在后续提取时清理。进程重启后需重新上传；主动重新提取会刷新缓存。审阅时可指定段号与类别补提，生成开场白前可以预览实际入选的启用条目，包括手动条目。请及时导出。模型生成的大量条目仍需要服务器和浏览器内存。只处理有权使用的文本。

## 开发验证

```powershell
python -m unittest discover -v
# 前端状态回归测试（需要 Node.js）
node --test test_frontend.js
```

测试使用受控模型响应验证分段、引文、激活策略以及上传和下载链路，不会使用真实密钥或产生模型费用。

在部署目录运行 `docker compose -f compose.yaml logs --timestamps --tail=150 -f extractor` 查看终端日志。页面运行日志里的 task 编号可用来筛选请求、响应及解析错误。

导入时可预览 TXT 开头，或直接粘贴正文。任务中展开「逐段查看请求、回复和候选」可按次读取发送的消息、模型返回的文本及通过校验的候选。本地复用的段会标明未请求上游。模型请求的缓存命中 token 数取自上游用量，缺少该字段时显示“未报告”。记录属于当前任务，保存在临时文件，丢弃任务或重启实例后释放。

在世界书审阅区可单独编排启用条目的插入参数。每批最多 12 条，编排理由保存在审阅页；任一批次失败会保留原参数。此步骤可跳过。

关闭页面会请求停止任务：正在等待的上游请求可能继续到返回或超时，但不会再提交后续段落、补提或重试。临时断线会自动重连；任务不存在或访问被拒绝时停止重连。开场白重新生成失败会保留当前手工草稿。引文必须为 5–100 字的连续原文，且不能只有标点。
